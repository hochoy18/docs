handoff

把当前会话压成一个可携带的交接文件，让下一个 agent 接手——它提供的是可搬运性，不是更好的压缩。

用途

/handoff 把对话压成一个 markdown 文件，写进操作系统临时目录（不是仓库）， 供一个新开的 agent 读取并接着干。

关键区别：/compact 压缩得好，但结果留在同一个窗口里，出不去。 handoff 压缩得不一定更好，但它给你一个文件——能换 harness、换目录、发给同事、能岔出去并行。

一句话判据

没有东西在「旅行」，就不要用 handoff。同 harness、同目录、同任务 → 用 /compact。

SKILL.md 全文

16 行。5 条指令，每条都对应一个已知的失效模式——它不是功能清单，是踩坑清单。

---
name: handoff
description: Compact the current conversation into a handoff document for another agent to pick up.
argument-hint: "What will the next session be used for?"
disable-model-invocation: true
---

Write a handoff document summarising the current conversation so a fresh agent can
continue the work. Save to the temporary directory of the user's OS - not the current workspace.

Include a "suggested skills" section in the document, naming which skills the next agent
should call the Skill tool for.

Do not duplicate content already captured in other artifacts (specs, plans, ADRs, issues,
commits, diffs). Reference them by path or URL instead.

Redact any sensitive information, such as API keys, passwords, or personally identifiable
information.

If the user passed arguments, treat them as a description of what the next session will
focus on and tailor the doc accordingly.
指令它在防什么
写到临时目录，不进仓库交接文档是「在途文档」，不是你要长期维护的产物
必须有 suggested skills 段意图无法从指针里推断出来，必须显式写
不复制已有产物，按路径引用两份真相必然漂移
脱敏凭据、PII、不可达的绝对路径
尊重 argument这是压缩函数的控制输入，不传就会把推理压平

核心原理：指针 + 意图

剥到最底一句话：一个 handoff 无法携带信息，它只能携带「指针 + 意图」。 接受这句话，整套设计就都是必然推论，不需要再背规则。

图 1 · handoff 是信封不是货车——真正的信息始终待在仓库里

由此可以反推出全部设计：

  • 载荷在仓库里 → 必须引用而非复制 → 复制会产生第二份会漂移的真相
  • 它是个指针不是产物 → 不该污染仓库 → 放临时目录
  • 意图无法从指针里推断 → 必须显式写（suggested skills + argument）
  • 指针可能悬空 → 交接后要验

四个触发场景

只有四个。「and only four」是刻意克制——一旦扩到第五个，它就退化成 /compact 了。

图 2 · 先问「有东西在旅行吗」，再问「用什么」
最常见的误用

把 /handoff 当成「更省事的 /compact」用。 原文说得更直接：「按这种方式读，它看起来就是个更差的 /compact，所以人们跳过它。」

误用的代价不是「没用」，而是白白付了一次有损压缩， 还留下一份会和仓库漂移的副本——比不用更糟。

与 compact / clear / subagent

五个选项（含「什么都不做」）各保留不同的东西。除「继续」外，其余全部都是把一手记录换成二手摘要——所以先排除「继续」。

分叉用法（最被跳过的一个）

它的描述读起来像「会话续接」，那样看确实像个更差的 /compact。 真正值得知道的是另一面：你留在原会话里，把一份上下文副本交给第二个 agent 并行干活。

图 4 · handoff 最有价值的用法：往返一次，而不是换掉当前会话

为什么值得这么绕一圈

你在设计讨论里攒下的推理，不值得为了跑一次代码而消耗掉。 工作跨越两次，原会话始终在线——你一次都不用重讲。

这也是 handoff 和 prototype 成为最近邻的原因—— prototype 天然住在自己的目录里，来回搬运正是为它准备的。

写什么 · 不写什么

图 5 · 右栏每一条都会让文档与仓库产生第二份、且会漂移的真相
最贵的失效模式：假设被固化成公理

文档只捕捉 what，不捕捉 why——这是常见批评。真正的风险比「信息缺失」更隐蔽： 下一个 agent 会信任这份文档，不会去复核它。 于是会话里那句没验证过的「X 还没实现」，一旦以确定语气写进去， 就成了后续一切推理的前提，而且没有任何东西会提示它是错的。

两个缓解手段：① 调用时传 argument——告诉它下一个会话要干什么，让它保留与目标相关的推理，而不是把一切压平； ② 交出去之前自己读一遍——把所有「只是假设」降级成「假设（未验证）」。

五个陷阱

倒过来问：做出一个烂 handoff，最短路径是什么？

#失败路径后果破解动作
1 什么都没「旅行」时用它 白付一次有损压缩，还留下会漂移的副本 先过四触发检查；四样都不是 → /compact
2 把假设写成事实 下一位 agent 把它当公理继承，后续推理全歪 交出前自己读一遍，逐条降级为「假设（未验证）」
3 粘贴进 claude "<summary>" 摘要里的反引号 / $(...) 被 shell 吃掉， 静默截断、不报错——新 agent 拿着残缺简报开工 永远指路径：读 <path>，然后继续
4 路径没记住 / 临时文件没了 下一位 agent 完全不知道从哪开始 立刻 cp 到持久位置，别等
5 交出后没验指针 悬空指针 → 下一个 agent 只能从头重建，handoff 彻底失效 交出后逐个 test -e
关于临时目录：文章描述与 macOS 现实有偏差

原文说 $TMPDIR，否则 /tmp（Windows %TEMP%）， 并提到「重启会清空 /private/tmp」。

本机实测：$TMPDIR 指向 /var/folders/tx/844rccxs1dl3j4b89x6wqt680000gn/T/—— macOS 上是按用户隔离的私有目录，既不是 /tmp 也不是 /private/tmp。 所以「重启清空」描述的是一个 fallback 根本没会用到的目录。

真实风险是隔离而非清理：换个用户、换个沙盒上下文，同一个路径根本不存在。 结论不变——立刻复制走。

与 claude-handoff

本仓库同时存在 ~/.claude/skills/claude-handoff/。 两者是同一骨架的两种 transport，不冲突，可共存。

两者的 5 条核心指令同源（目的、suggested skills、不复制、脱敏、尊重 argument）， 其中「不复制已有产物」一条逐字相同。 唯一的实质变量是载荷怎么送出去：

两点差异要知道：claude-handoff 另有第 6 条指令—— 必须用 --name 起一个描述性名字（它决定任务列表、会话选择器和终端标题里显示什么）； 另外因为摘要直接变成 agent 的 prompt，它的脱敏措辞比 handoff 更强调。 它比 handoff 多一行，多一条规则。

关于 agents/openai.yaml

handoff/agents/openai.yaml 里的 allow_implicit_invocation: false 是给 Codex / OpenAI 那套 harness 的兼容垫片，等价于 Claude Code frontmatter 里的 disable-model-invocation: true——两边作用一致：禁止 agent 自动触发，只能你手动敲。 你的安装已覆盖四个触发场景里的第一项（换 harness）。

交出前自检

文章给的验收标准是「感觉」，这里是可以直接跑的四条：

H=~/Desktop/handoff-latest.md

# 1. 体量：应该是对话的一个零头。超过 ~150 行通常是在复制而不是在引用
wc -l "$H"

# 2. 无密钥（期望零命中）
grep -nEi 'sk-|api[_-]?key|password|secret' "$H"

# 3. 无家目录绝对路径（PII 泄漏，agent 不会自动脱敏）
grep -n '/Users/你的用户名' "$H"

# 4. 指针可达：逐个 test -e
grep -oE '[A-Za-z0-9_./-]+\.(md|py|ts|tsx|yaml|json)' "$H" \
  | sort -u | while read -r p; do [ -e "$p" ] || echo "悬空: $p"; done

人工过一遍的三条（脚本查不出来）：

  • argument 传了吗？没传 → 文档会把推理压平，丢掉 why
  • 每条未验证的判断都降级了吗？「假设（未验证）：…」
  • 有「已排除的路」吗？这是 CONTEXT.md / ADR 覆盖不到、只有交接文档能承载的部分
