grill-me

grill-with-docs 的轻量版——只调 grilling，不写任何文件。

用途

当你不在仓库里、或者只是想聊个设计，不希望产生任何 CONTEXT.md / ADR 文件变更—— 用 /grill-me 启动一次纯净的采访。

它做的事：调一次 grilling skill。 它不调 domain-modeling——所以不会写文件。

SKILL.md 全文

5 行（4 行 frontmatter + 1 行调用指令）：

---
name: grill-me
description: A relentless interview to sharpen a plan or design.
disable-model-invocation: true
---

Call the Skill tool with "grilling".

与 grill-with-docs 的差异

两者几乎一字不差——只有两处删减：

# grill-with-docs grill-me
3 description: A relentless interview to sharpen a plan or design, → description: A relentless interview to sharpen a plan or design.
4   which also creates docs (ADR's and glossary) as we go.  
7 Call the Skill tool twice, for "grilling" and "domain-modeling". → Call the Skill tool with "grilling".

语义对比

维度 grill-with-docs grill-me
调几次 Skill 2 次（grilling + domain-modeling） 1 次（只 grilling）
写文件？ ✅ 写 CONTEXT.md / docs/adr/ ❌ 不写任何文件
需要上下文？ 需要仓库（落档需要路径） 不需要（无副作用）
对仓库的修改 会创建/修改 CONTEXT.md、docs/adr/*.md 零修改
disable-model-invocation true true（同样独占）
典型场景 在 GitHub repo 里打磨设计 无目录、纯聊天、临时评审

何时用 / 不用

用 grill-me

  • 无工作目录 / 在随便一个目录聊设计
  • 临时评审一个想法，不希望污染 CONTEXT.md
  • 想测试 grilling 引擎本身
  • 做设计讨论、不打算立刻 commit 任何东西

用 grill-with-docs

  • 在 GitHub repo 里、要沉淀到 CONTEXT.md
  • 会触发不可逆决定、需要 ADR 留档
  • 后续要把成果接上 /to-spec → /to-tickets

两个都不要用

  • 想自动化 issue 处理 / bug 修复 → 调 /triage / /diagnosing-bugs
  • 想直接跑 grilling 引擎本身 → 直接调 grilling，不走 wrapper
  • 已经有足够设计、想直接开始实现 → 跳过 grilling，直接 /to-spec
